關於我

我是宋祐嘉（Ken），專注 AI 應用開發的軟體工程師。對寫程式的興趣始於大學，之後在台大資訊培訓班與緯育課程持續精進，一路延伸到 Java 後端、Python 應用與前端框架，現在把重心放在「把 LLM 接進實際功能，並確保輸出可信」這件事上。

我最大的特質是扎實的基本功與自我學習能力——能快速吸收新技術，並把它實際做出成果。在校期間透過畢業專題把技術落地，完整走過軟硬整合到雲端回傳的鏈路。

我的工作風格是以個人實力為核心、以 AI 為輔助：架構設計、邏輯拆解與程式品質由我親手掌握，AI（Claude 等）則用來加速設計、除錯與重構。這也是我做 LLM 功能時特別在意輸出驗證與品質閘門的原因——模型會出錯，但交付出去的東西不能出錯。

我在 2026 年 3 月到 9 月擔任資訊科技老師，同時接前後端與資料庫相關的家教。教學讓我養成一種習慣：把複雜的技術概念，拆解成對方（不管是學生、家長還是非技術背景的人）聽得懂的說法，並確認對方真的理解、真的能動手做。為此我自行編寫了一整套互動式程式教學平台。目前已離職，專心投入 AI 應用開發職涯，可立即上班。

AI 應用開發

模型會出錯，但交付出去的東西不能出錯。以下每一項都已經跑在實際流程裡，而且附得出實測數據——還沒 ship 的放在最後一段，不混在裡面。

已經動手做過的部分

LLM API 串接

實際串接 Anthropic 與 OpenAI 的 API 進功能裡：金鑰管理、逾時與重試、錯誤回退，以及回應格式不如預期時怎麼辦。用在教學內容自動化、文件轉結構化資料、網站文案產出與開發流程工具四類場景。

Prompt 設計與輸出驗證

Prompt 寫完不算完成。我替輸出定義可檢查的條件再往下走：教材裡 75 題「輸出為何」全部拿去實際編譯執行、把程式輸出和標示的正解逐題比對，改完 0 題不符。

規則式品質閘門

在模型輸出與交付之間放一層規則閘門，不符就攔下。實測攔下：6 題標錯的正解、2 題無法作答、445 處讓程式編譯不報錯卻輸出全錯的字串破壞、7 個 JS 執行期錯誤、63 個斷掉的錨點——修正後全部歸零。

結構化資料抽取

把非結構化文字轉成下游能直接用的結構化資料，並確保欄位型別與必填條件成立。教材的 2100 題靜態題庫就是這樣抽取與校驗的，結構問題從 67 題降到 0。

Agent 開發工具日常使用

每天以 Claude Code／Cowork 完成多步驟開發任務，實際體會工具呼叫、任務拆解與失敗重試在真實開發裡的取捨。本站與上述驗證流程都是這樣做出來的——是天天在用的工作方式，不是讀過的概念。

接得進真實系統

Voyago 預訂平台（Vue 3 + Spring Boot 3 + MySQL 8 + JWT）證明我能把資料庫、後端、前端三層打通，還處理了限流、快取、N+1 與後端權限控管——AI 功能最後都要落在這樣的既有系統裡。

目前正在補強：RAG 檢索架構、MCP、Docker 地端部署、向量資料庫。這些我還沒 ship 過，所以分開列——上面那些是可以被問到底的。歡迎直接約時間聊聊，我可以當場展示作品集與 Demo。

Voyago 歐洲自助遊預訂平台

從資料庫設計、後端 API 到前端畫面，由我一人獨立完成。我刻意補上課堂範例常跳過、但實務一定會遇到的東西：登入除了帳密還接 Google ID Token 後端驗證、密碼走 BCrypt、登入端點做限流擋暴力破解；列表頁用 LAZY + fetch join 解 N+1、熱門查詢上 Caffeine 快取；權限不靠前端藏按鈕，後端以 @PreAuthorize 強制，STAFF 專屬端點就算被繞過也擋得住。單元測試接 GitHub Actions CI，API 文件由 springdoc 自動產出。

展示站跑的是純前端示範模式：免費後端閒置會睡，一睡 Demo 就變死連結，所以前端內建 mock fallback（同一套 UI 與 API 介面），註冊、登入、搜尋、下訂流程照樣走得完。完整三層可在本機一鍵啟動，面試時我可以當場跑給你看。
